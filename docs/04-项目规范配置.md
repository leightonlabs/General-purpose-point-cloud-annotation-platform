# 点云项目与标注规范配置

| 项 | 内容 |
|----|------|
| 文档编号 | PCD-SPEC-CONFIG-001 |
| 版本 | V1.0（一期） |
| 日期 | 2026-10-22 |
| 适用 | 项目管理员、规范维护人 |

点云项目沿用原平台“项目钉定规范版本、任务冻结版本”的机制。本文规定点云项目**怎么建、规范里的类别怎么写**，以及哪些需求靠配置解决、哪些必须开发。

---

## 1. 建项目

| 项 | 取值 | 影响 |
|---|---|---|
| 媒体类型 | 点云（`lidar`） | 作业台加载点云编辑器；导入时按点云扩展名收文件 |
| 标注类型 | **立体框 / 点云**（`cuboid`）或 **点云语义分割**（`point_seg`） | 决定作业台默认进入的模式与结算单位（立体框按目标计、分割按条计） |
| 规范 | 钉定一个已发布的本体版本 | 类别、几何、属性、导出码均来自该版本 |
| 质检 / 审核 | 一期建议都开启（`require_review` / `require_audit`） | 见 [06 作业流程](./06-作业流程与质量规范.md) |

点云媒体下目录中还列有“关键点”“实例分割（多边形）”“整图分类”等类型，**一期点云编辑器没有对应工具，不得选用**。

## 2. 类别几何决定作业模式

每个类别在规范里声明允许的几何。点云相关的两种：

| 几何 | 含义 | 作业台表现 |
|---|---|---|
| `cuboid`（立体框） | 该类以三维框标注 | 出现在目标模式可用类别中 |
| `point_seg`（点云分割） | 该类以逐点标签标注 | 出现在分割模式类别列表中 |

模式开启规则（与代码一致）：

1. 任一类别声明 `cuboid` → 开启**目标模式**；任一类别声明 `point_seg` → 开启**分割模式**；两者都有 → 工具栏出现“目标 / 分割”切换（快捷键 M）。
2. 一个类别可以同时声明两种几何（例如“车辆”既拉框又分割）。
3. 新建点云类别时规范库默认填 `cuboid`；**分割项目必须在规范库中为分割类别勾选“点云分割”并发布新版本**，否则作业台提示“冻结规范中没有声明…无法作业”。
4. 兼容旧数据：类别完全未声明几何时，按项目标注类型归入对应模式。

后端提交校验同样按几何检查：立体框的类别必须允许 `cuboid`，被逐点使用的类别必须允许 `point_seg`。

## 3. 类别字段填写规范

| 字段 | 规范 |
|---|---|
| 名称 | 作业员可见的中文名，项目内唯一 |
| 颜色 | 必填，十六进制；分割类别之间颜色要可区分，避免与未标注点（压暗的高度色）和高亮色（黄色）接近 |
| 导出码 `exportCode` | 交付使用的英文类名，**不含空格**（OpenPCDet 以空格分列，平台会把空格替换为下划线） |
| 类别编号 `categoryId` | 分割项目必填：即 SemanticKITTI `.label` 中的语义 id，1–65535 且项目内唯一；0 保留为未标注。未填时按类别顺序自动编号，**规范调整顺序会改变 id**，因此交付项目必须显式填写 |
| 停用 | 类别只能停用不能删除；停用后，历史分割结果中的该类在类别列表中标红，历史立体框在提交校验时报错，均须改标 |

## 4. 属性设计

沿用规范库属性能力（枚举、文本、必填、条件显示）。点云项目建议：

| 场景 | 建议属性 | 必填 |
|---|---|---|
| 智驾目标 | 遮挡程度（无 / 部分 / 严重）、截断（是 / 否）、运动状态（静止 / 运动 / 未知） | 按甲方规范 |
| 分割 | 一般不设逐点属性；帧级属性（天气、场景）用整帧属性 | 否 |

规则：

- 属性取值写成枚举，不用自由文本表达可枚举的状态；
- “必填”只给验收必须的属性，避免增加无效工作量；
- 属性的 `attrId` 一经发布不得改动（结果按 `attrId` 存值）。

## 5. 跟踪 ID 规范

| 规则 | 说明 |
|---|---|
| 作用域 | 同一序列（同一辆采集车同一段连续采集）内，同一个物理目标在所有帧使用同一个 `trackId` |
| 形式 | 建议纯数字字符串（作业台“自动编号”按现有最大数字 + 1 生成） |
| 唯一性 | 同一帧内不得重复（平台强制） |
| 离开再出现 | 是否沿用原 ID 由甲方规范决定，须写入项目说明 |
| 一期限制 | 跨帧一致性靠作业员按序列顺序作业与质检抽查保证；跨帧自动检查与关联工具在二期 |

不需要跨帧身份的项目（单帧检测）不填 `trackId`。

## 6. 分割类别设计规范

1. **类别互斥且覆盖完整**：每个点只能属于一个类别；作业范围内的每个点都要有归属。
2. **必须有兜底类**：设置“其他 / 忽略”类，用于确实无法判断或不需要细分的点，使“未标注 = 还没做”。
3. **作业范围**：若只标注某个范围（如半径 50 m 内），在项目说明中写明，并约定范围外的点是标“忽略”还是保持未标注；一期平台对未标注只做提醒，不强制。
4. **边界规则**：写明目标与地面接触处、相邻目标之间的归属原则（例如“轮胎触地点归车辆”）。

## 7. 版本发布与变更

| 变更 | 做法 | 对进行中任务的影响 |
|---|---|---|
| 改名、改色、加属性、加类别 | 规范库草稿修改后发布新版本，项目升级钉定 | 只影响之后新建的任务与新导入样本 |
| 停用类别 | 同上 | 新任务不可选；旧结果中的该类须改标后才能提交 |
| 改几何声明 | 同上 | 同上；已有结果不会被改写 |
| 改 `categoryId` / `exportCode` | 同上，并通知交付方 | 影响之后的导出文件 |

规范版本发布前由规范维护人与项目经理双人确认，发布记录写入项目说明。

## 8. 配置还是开发：判定表

| 需求 | 处理 |
|---|---|
| 换类别、颜色、属性、必填项 | 配置（规范新版本） |
| 只拉框 / 只分割 / 既拉框又分割 | 配置（几何声明） |
| 甲方要求交付 KITTI 3D / nuScenes / 专有 JSON | 开发导出适配器（以 [03 结果协议](./03-标注结果协议.md) 为输入） |
| 新格式输入、非 KITTI 布局的 BIN | 预处理转换；高频时扩展解析器 |
| 三维折线、区域、实例分割、序列作业、相机联动 | 开发能力模块（见 [07 路线图](./07-研发规范与一期计划.md#8-路线图)） |

## 9. 派工前配置检查清单

| # | 检查 | 通过标准 |
|---|---|---|
| C1 | 媒体类型、标注类型 | 点云 + 立体框 / 点云语义分割 |
| C2 | 类别几何 | 拉框类声明 `cuboid`；分割类声明 `point_seg` |
| C3 | 类别颜色、导出码、编号 | 颜色可区分；导出码无空格；分割项目 `categoryId` 显式且唯一 |
| C4 | 兜底类 | 分割项目存在“其他 / 忽略”类 |
| C5 | 属性 | 必填项与甲方规范一致 |
| C6 | 质检 / 审核开关、驳回策略 | 已按合同设置 |
| C7 | 试标 | 用 20–50 帧试标并通过一次完整“提交 → 质检 → 导出 → 核验”后再大规模派工 |

## 10. 配置示例

**A. 智驾目标检测（含跟踪 ID）**

| 类别 | 几何 | 导出码 | 属性 |
|---|---|---|---|
| 小汽车 | cuboid | Car | 遮挡（必填）、截断、运动状态 |
| 卡车 | cuboid | Truck | 同上 |
| 行人 | cuboid | Pedestrian | 遮挡（必填） |
| 骑行者 | cuboid | Cyclist | 遮挡（必填） |

**B. 点云语义分割**

| 类别 | 几何 | categoryId | 导出码 |
|---|---|---|---|
| 路面 | point_seg | 40 | road |
| 人行道 | point_seg | 48 | sidewalk |
| 建筑 | point_seg | 50 | building |
| 植被 | point_seg | 70 | vegetation |
| 车辆 | point_seg | 10 | car |
| 其他 / 忽略 | point_seg | 99 | other |

**C. 混合（车辆拉框 + 地面分割）**：车辆类声明 `cuboid` 和 `point_seg`，地面类只声明 `point_seg`；作业员先在目标模式拉框，再到分割模式用“框内点赋类（I）”把框内点赋给车辆，其余点按区域赋类。
