点云项目沿用原平台“项目钉定规范版本、任务冻结版本”的机制。本文规定点云项目**怎么建、规范里的类别怎么写、作业方式怎么配**，以及哪些需求靠配置解决、哪些必须开发。

---

## 1. 建项目

| 项 | 取值 | 影响 |
|---|---|---|
| 媒体类型 | 点云（`lidar`） | 作业台打开点云作业台；导入时按点云扩展名收文件 |
| 标注类型 | **立体框 / 点云**（`cuboid`） | 点云作业台本身不读取标注类型；它决定平台的结算单位（见下） |
| 规范 | 钉定一个已发布的本体版本 | 类别、颜色、属性、导出码、编号均来自该版本 |
| 质检 / 审核 | 一期建议都开启（`require_review` / `require_audit`） | 见 [06 作业流程](./06-作业流程与质量规范.md) |

- 点云媒体下目录中还列有“关键点”“实例分割（多边形）”“整图分类”等类型，**点云作业台没有对应工具，不得选用**。
- **结算**：“立体框 / 点云”类型的标注环节按“目标”计价，计量为提交时整包 `shapes` 的个数（即立体框个数）。**纯分割项目**没有立体框，应在费率中只设“按条单价”、把目标单价与基础价设为 0，平台会自动按条计价；混合项目按合同约定选择按目标或按条。质检、审核环节始终按条。

## 2. 类别作业方式

每个类别可以“拉立体框”“逐点分割”或两者都做，在点云作业台的 **项目工具 → 类别作业方式** 中配置，存于点云模块自己的配置表 `lbl_pc_project_config`，按项目、按 `classId` 生效。

| 作业方式 | 作业台表现 | 后端提交校验 |
|---|---|---|
| 立体框（`cuboid`） | 该类出现在目标模式的类别列表中 | 立体框的类别必须含此方式 |
| 逐点分割（`point_seg`） | 该类出现在分割模式的类别列表中 | 被逐点使用的类别必须含此方式 |

规则（与代码一致）：

1. **未配置的类别默认只拉立体框**。因此纯拉框项目无需任何配置；分割或混合项目必须在派工前配置。
2. 任一类别含“立体框” → 开启目标模式；任一类别含“逐点分割” → 开启分割模式；两者都有 → 编辑器出现“目标 / 分割”切换（快捷键 M）。所有类别都只做分割时，作业台直接进入分割模式。
3. 每个类别至少选一种方式；一个类别可以同时选两种（例如“车辆”既拉框又分割）。
4. 保存后对本项目**所有**点云任务立即生效（已打开的作业台刷新后生效），不需要发布规范新版本。
5. 进入项目工具的入口：在作业台顶栏点“项目工具”。需要“项目编辑”（`labeling:project:update`）权限才能保存作业方式，“数据集导出”权限才能导出；没有这两项权限的账号看不到该按钮。项目管理员可在任务详情中以只读方式打开任一明细后进入。
6. 规范库中点云类别的“几何”字段保持默认的“立体框”即可，点云作业台不读取它。

> 改作业方式前先确认已有结果：把某类从“逐点分割”中去掉后，已用该类标注的点在下次提交时会被判为硬错误，需要改标。

## 3. 类别字段填写规范

| 字段 | 规范 |
|---|---|
| 名称 | 作业员可见的中文名，项目内唯一 |
| 颜色 | 必填，十六进制；分割类别之间颜色要可区分，避免与未标注点（压暗的高度色）和高亮色（黄色）接近 |
| 导出码 `exportCode` | 交付使用的英文类名，**不含空格**（OpenPCDet 以空格分列，平台会把空白替换为下划线）；未填时依次取英文名、中文名 |
| 类别编号 `categoryId` | 即 SemanticKITTI `.label` 与 `classes.json` 中的语义 id，1–65535；0 保留为未标注。未填时按类别顺序从 1 起取未被占用的编号，**规范调整类别顺序会改变自动编号**，因此分割交付项目必须显式填写。多个类别填同一编号表示交付时合并为同一语义类 |
| 停用 | 类别只能停用不能删除；停用后，历史分割结果中的该类在类别列表中标红“已不在规范中”，历史立体框在提交校验时报错，均须改标 |

## 4. 属性设计

沿用规范库属性能力。点云作业台的属性表单支持：有选项的属性显示为下拉，其余为文本输入；必填标红星；一层条件显示（`visibleWhen`：某属性等于某值时才显示 / 才必填）；子属性。

| 场景 | 建议属性 | 必填 |
|---|---|---|
| 智驾目标 | 遮挡程度（无 / 部分 / 严重）、截断（是 / 否）、运动状态（静止 / 运动 / 未知） | 按甲方规范 |
| 分割 | 不设逐点属性 | — |

规则：

- 属性取值写成选项，不用自由文本表达可枚举的状态；
- “必填”只给验收必须的属性，避免增加无效工作量；
- 属性的 `attrId` 一经发布不得改动（结果按 `attrId` 存值）；
- 一期点云作业台**没有整帧属性**（天气、场景等），需要时作为二期需求提出。

## 5. 跟踪 ID 规范

| 规则 | 说明 |
|---|---|
| 作用域 | 同一序列（同一辆采集车同一段连续采集）内，同一个物理目标在所有帧使用同一个 `trackId` |
| 形式 | 建议纯数字字符串（编辑器“自动编号跟踪 ID”按本帧现有最大数字 + 1 生成） |
| 唯一性 | 同一帧内不得重复，≤ 64 字符（平台强制） |
| 离开再出现 | 是否沿用原 ID 由甲方规范决定，须写入项目说明 |
| 一期限制 | 跨帧一致性靠作业员按序列顺序作业与质检抽查保证；跨帧自动检查与关联工具在二期 |

不需要跨帧身份的项目（单帧检测）不填 `trackId`。

## 6. 分割类别设计规范

1. **类别互斥且覆盖完整**：每个点只能属于一个类别；作业范围内的每个点都要有归属。
2. **必须有兜底类**：设置“其他 / 忽略”类，用于确实无法判断或不需要细分的点，使“未标注 = 还没做”。
3. **作业范围**：若只标注某个范围（如半径 50 m 内），在项目说明中写明，并约定范围外的点是标“忽略”还是保持未标注；一期平台对未标注只做提醒，不强制。
4. **边界规则**：写明目标与地面接触处、相邻目标之间的归属原则（例如“轮胎触地点归车辆”）。

## 7. 版本发布与变更

| 变更 | 做法 | 对进行中任务的影响 |
|---|---|---|
| 改名、改色、加属性、加类别 | 规范库草稿修改后发布新版本，项目升级钉定 | 只影响之后新建的任务与新导入样本 |
| 停用类别 | 同上 | 新任务不可选；旧结果中的该类须改标后才能提交 |
| 改类别作业方式 | 项目工具中修改，立即生效 | 影响本项目全部任务（§2 提示） |
| 改 `categoryId` / `exportCode` | 规范发布新版本，并通知交付方 | 影响之后的导出文件（导出按项目当前钉定的规范版本取类别） |

规范版本发布、作业方式调整前由规范维护人与项目经理双人确认，记录写入项目说明。

## 8. 配置还是开发：判定表

| 需求 | 处理 |
|---|---|
| 换类别、颜色、属性、必填项 | 配置（规范新版本） |
| 只拉框 / 只分割 / 既拉框又分割 | 配置（项目工具 → 类别作业方式） |
| 交付通用格式（逐帧 JSON、OpenPCDet、SemanticKITTI） | 配置即可（项目工具 → 导出点云训练包） |
| 甲方要求交付 KITTI 3D / nuScenes / 专有 JSON | 开发导出写出器（以 [03 结果协议](./03-标注结果协议.md) 为输入） |
| 新格式输入、非 KITTI 布局的 BIN | 预处理转换；高频时扩展解析器 |
| 三维折线、区域、实例分割、整帧属性、序列作业、相机联动 | 开发能力模块（见 [07 路线图](./07-研发规范与一期计划.md#9-路线图)） |

## 10. 配置示例

**A. 智驾目标检测（含跟踪 ID）**——作业方式全部默认（立体框），无需配置。

| 类别 | 作业方式 | 导出码 | 属性 |
|---|---|---|---|
| 小汽车 | 立体框 | Car | 遮挡（必填）、截断、运动状态 |
| 卡车 | 立体框 | Truck | 同上 |
| 行人 | 立体框 | Pedestrian | 遮挡（必填） |
| 骑行者 | 立体框 | Cyclist | 遮挡（必填） |

**B. 点云语义分割**——全部类别只勾“逐点分割”，作业台直接进入分割模式；费率按条。

| 类别 | 作业方式 | categoryId | 导出码 |
|---|---|---|---|
| 路面 | 逐点分割 | 40 | road |
| 人行道 | 逐点分割 | 48 | sidewalk |
| 建筑 | 逐点分割 | 50 | building |
| 植被 | 逐点分割 | 70 | vegetation |
| 车辆 | 逐点分割 | 10 | car |
| 其他 / 忽略 | 逐点分割 | 99 | other |

**C. 混合（车辆拉框 + 地面分割）**：车辆类勾“立体框”和“逐点分割”，地面类只勾“逐点分割”；作业员先在目标模式拉框，再到分割模式用“框内点赋类（I）”把框内点赋给车辆，其余点按区域赋类。
