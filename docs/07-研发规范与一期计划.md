## 1. 代码与模块规范

### 1.1 分层

| 层 | 文件 | 约束 |
|---|---|---|
| 纯计算 | `pointCloudFormats.ts` `pointLabels.ts` `cloudGeometry.ts` `cloudColors.ts` `lidarValidation.ts` | **不得引入 three.js、Vue、Element Plus 与 `@/` 别名运行时导入**（只允许 `import type`），保证可在 Node 中直接单测 |
| 渲染 | `pointCloudScene.ts` | 只管显示与拾取，不持有标注结果；坐标一律为局部坐标 |
| 交互 | `LidarEditor.vue` `ThreeViewPanel.vue` | 结果只通过 `update:snapshot` 写回壳；变更前发 `before-mutate`，变更后发 `dirty` |
| 壳 | `WorkbenchShell.vue` | 点云相关改动只做集成（快照字段、撤销、校验、质检钉），不写点云业务逻辑 |
| 后端 | `PointSegCodec` `PointCloudAnnotationValidator` `DatasetPackZipWriter` | 工具类无状态；点云内容不建表，继续整包 JSON |

### 1.2 数据与响应式

1. 点坐标、着色、标签、投影缓存等大数组**不得放进 Vue 深响应式**：用普通变量或 `shallowRef`。
2. 模板或 `computed` 需要感知大数组状态时，另设一个响应式标记（如 `labelsReady`）。*一期曾因 `computed` 依赖普通变量导致直接进入分割模式时工具一直禁用，已修复，引以为戒。*
3. 视口与几何计算使用局部坐标，落库使用原始坐标；转换只在 `toLocalBox` / `fromLocalBox` 两处进行。
4. 不得对点序做任何过滤、排序、降采样后再写标签。

### 1.3 协议变更

1. 结果协议只增可选字段；改编码必须换 `encoding` 名称。
2. 改动编解码时必须**同时**改 TS（`pointLabels.ts`）与 Java（`PointSegCodec.java`），并更新双方共用的测试向量。
3. 协议变更同步更新 [03-标注结果协议](./03-标注结果协议.md) 与 `labeling-server/docs/详细设计/点云作业台.md`。

### 1.4 其它

- 不新增 npm / Maven 依赖（沿用原项目规则）；需要时先评审。
- 注释、提示文案用中文；面向作业员的报错要说清“发生了什么、怎么办”。
- 性能敏感路径（逐点循环）避免在循环内分配对象、调用闭包外的响应式值。

## 2. 测试规范

### 2.1 提交前必须通过

| 检查 | 命令 | 覆盖 |
|---|---|---|
| 前端类型检查 | `cd labeling-admin-web && npx vue-tsc -b` | 全部前端 |
| 前端单测 | `npm run test:unit`（Node ≥ 22.6，内置 test runner，无新依赖） | 解析、编解码、几何、选区、校验（21 项） |
| 后端单测 | `cd labeling-server && mvn test` | 编解码（含前端向量）、提交校验、质检写回、导出包（9 项） |

### 2.2 浏览器冒烟（改动编辑器交互时）

用 Playwright（环境已装 Chromium）在本地 Vite 下挂载 `LidarEditor` 的测试页，覆盖：加载、拉框、贴合、方向键与掉头、三视图拖边/旋转、分割矩形/框内点/笔刷擦除、撤销、保存刷新恢复、点云不一致保护、200 万点性能。测试页与合成数据**不提交到仓库**；合成场景生成方法见附录 A。

### 2.3 新格式 / 新导出的测试要求

- 每种新输入格式：至少一个真实样本 + 一个手工构造的边界样本（无效点、大坐标、最小文件）。
- 每种新导出适配器：一组“输入整包 → 期望文件”的固定样例，纳入后端单测。

## 3. 部署与配置参数（点云项目）

| 参数 | 位置 | 建议值 | 原因 |
|---|---|---|---|
| `OSS_MAX_FILE_SIZE` | 后端环境变量 | ≥ 200 MB | 默认 10 MB，单帧点云常见 2–50 MB |
| `OSS_MAX_ZIP_UPLOAD_SIZE` | 后端环境变量 | 默认 200 MB，可按批次调大 | zip 导入 |
| `spring.servlet.multipart.*` | `application.yml` | 与上面一致 | 仅影响经后端中转的上传 |
| 反向代理请求体上限（如 nginx `client_max_body_size`） | 网关 | ≥ 32 MB | 草稿/提交 JSON 含分割层，可达数 MB |
| MySQL `max_allowed_packet` | 数据库 | ≥ 64 MB | 写入大 JSON |
| 对象存储 CORS | 存储桶 | 允许作业台域名 `GET`，暴露 `Content-Length` | 编辑器用 `fetch` 下载点云二进制 |
| 预览签名有效期 `OSS_SIGNED_URL_EXPIRE_SECONDS` | 后端环境变量 | 默认 1800 s 可用 | 点云在打开时一次下载；超时后刷新页面即可 |
| 客户端 | 作业电脑 | Chrome/Edge 稳定版、WebGL 2、内存 ≥ 16 GB、独立显卡优先 | 百万级点渲染与选区 |

无需数据库迁移：标注类型目录（新增 `point_seg`）在后端启动时自动幂等写入；结果仍存于 `annotations_json`。

| 风险 | 影响 | 应对 |

## 10. 已知问题与观察（供原项目维护者参考）

1. **已修复**：原提交校验会把 `cuboid` 图形改写成 `rect`（三维几何丢失），点云框提交后无法再显示；本次在 `OntologyAnnotationValidator` 中保留立体框几何，并有单测覆盖。
2. **已修复**：质检写回（保存批注、通过）原先只写回整包模型内字段，会丢失立体框三维字段与点云层；现从提交原稿抄回未建模字段。该修复同样让视频轨迹等未建模字段在质检写回时得以保留。
3. **观察，未改动**：同一校验方法对 `ellipse`、`mask`、`polyline` 等图像几何也走“按 bbox 重建为 rect”的分支，提交后类型可能被改写。点云范围外，未做修改，建议图像模块负责人确认。
4. 解析目前在主线程进行，数百万点的 ASCII 文件会短暂卡顿；二期移到 Web Worker。

## 附录 A：合成测试场景

研发冒烟使用合成的车载场景（约 19 万点）：极坐标分布的地面（z = −1.7 m，近密远疏）、三辆不同朝向的车（只采样外表面）、一个行人柱体、一根杆、一面墙，并插入两个 NaN 占位点；同时写出 binary PCD 与 KITTI BIN 两份，用于验证两种格式摘要一致。性能测试另生成 200 万随机点 BIN。生成脚本放在研发个人目录，不入库；需要时可按上述描述重写。
