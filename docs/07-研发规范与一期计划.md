### 1.3 合并约定

1. 点云分支定期合入主干最新代码；因只改点云目录，正常情况下不会产生冲突。
2. 合入后必须跑 §3 全部检查；依赖清单中的接口有变化时，在点云模块内适配。
3. 点云模块不复用其它工作台的未完成组件（壳的保存 / 撤销 / 提交、图像编辑器工具等），需要的能力在点云目录内自建。

## 2. 代码规范

### 2.1 分层

| 层 | 文件 | 约束 |
|---|---|---|
| 纯计算 | `pointCloudFormats.ts` `pointLabels.ts` `cloudGeometry.ts` `cloudColors.ts` `lidarValidation.ts` `pointCloudResult.ts` `pointCloudHistory.ts` `pointCloudTypes.ts` | **不得引入 three.js、Element Plus 与 `@/` 别名的运行时导入**（只允许 `import type`；`pointCloudHistory.ts` 仅用 Vue `ref`），保证可在 Node 中直接单测 |
| 渲染 | `pointCloudScene.ts` | 只管显示与拾取，不持有标注结果；坐标一律为局部坐标 |
| 编辑器 | `PointCloudEditor.vue` `ThreeViewPanel.vue` | 结果只通过 `update:result` 交给作业台；变更前发 `before-mutate`（记撤销点），变更后发 `dirty`；不直接调接口 |
| 作业台 | `PointCloudWorkbench.vue` `pointCloudApi.ts` | 任务、保存、撤销、提交、质检、项目工具；唯一调用后端的地方 |
| 入口 | `LidarEditor.vue` | 只做全屏挂载与壳约定的保持，不写业务逻辑 |
| 后端接口 / 服务 | `PointCloudController` `PointCloudServiceImpl` | 服务方法 `@Transactional`：先写整包再调 `TaskService` 流转，失败整笔回滚 |
| 后端工具 | `PointCloudResultValidator` `PointSegCodec` `PointCloudModes` `PointCloudExportWriter` | 无状态静态方法，可脱离 Spring 单测；点云内容不拆表，继续整包 JSON |

### 2.2 数据与响应式

1. 点坐标、着色、标签、投影缓存等大数组**不得放进 Vue 深响应式**：用普通变量或 `shallowRef`。
2. 模板或 `computed` 需要感知大数组状态时，另设一个响应式标记（如 `labelsReady`）。*一期曾因 `computed` 依赖普通变量导致直接进入分割模式时工具一直禁用，已修复，引以为戒。*
3. 视口与几何计算使用局部坐标，落库使用原始坐标；转换只在 `toLocalBox` / `fromLocalBox` 两处进行。
4. 不得对点序做任何过滤、排序、降采样后再写标签。
5. 拖拽过程中不做 O(N) 重算（框内高亮、统计等），松手后统一刷新。

### 2.3 协议与接口变更

1. 结果协议只增可选字段；改编码必须换 `encoding` 名称。
2. 改动编解码时必须**同时**改 TS（`pointLabels.ts`）与 Java（`PointSegCodec.java`），并更新双方共用的测试向量（[03 §5.1](./03-标注结果协议.md#51-rle-varint-v1-编码)）。
3. 校验规则前后端同步修改（`lidarValidation.ts` 与 `PointCloudResultValidator.java`），并更新 [03 §7](./03-标注结果协议.md#7-校验规则)。
4. 新增点云接口一律放在 `/api/labeling/pointcloud/**`，更新 [03 §8](./03-标注结果协议.md#8-点云接口)。

### 2.4 其它

- 不新增 npm / Maven 依赖（沿用原项目规则）；需要时先评审。
- 新表、新字段只通过 `labeling_pointcloud_migrate.sql` 追加，语句幂等，不建外键。
- 注释、提示文案用中文；面向作业员的报错要说清“发生了什么、怎么办”。
- 性能敏感路径（逐点循环）避免在循环内分配对象、调用闭包外的响应式值。

## 3. 测试规范

### 3.1 提交前必须通过

| 检查 | 命令 | 覆盖 |
|---|---|---|
| 前端类型检查与构建 | `cd labeling-admin-web && npm run build` | 全部前端（含 `vue-tsc`） |
| 前端单测 | `cd labeling-admin-web && node --experimental-strip-types --no-warnings --test 'tests/pointcloud/*.test.ts'`（Node ≥ 22.6，内置 test runner，无新依赖、无 npm 脚本） | 格式解析与摘要、标签编解码、提交校验、结果往返（24 项） |
| 后端单测 | `cd labeling-server && mvn test -Dtest='com.pmsm.zs.labeling.pointcloud.**.*Test'` | 编解码（含前端向量）、严格 / 草稿校验、导出包、服务与中台的调用顺序（15 项） |

### 3.2 浏览器冒烟（改动作业台或编辑器交互时）

用 Playwright（环境已装 Chromium）在本地 Vite 下打开真实路由 `/workbench/:itemId`，以拦截 `/api/` 请求的方式模拟后端，覆盖：

- 全屏接管，壳的按键（Enter、方向键、`[`、`h`、`n`）不触发导航或提交，壳的保存 / 提交接口零调用；
- 拉框、贴合、方向键与掉头、三视图拖边 / 旋转；必填属性缺失阻止提交；
- 分割矩形 / 框内点 / 笔刷擦除；撤销、重做；自动保存草稿；提交后进入下一条；
- 质检：对框提问题 → 驳回，驳回理由与问题正确，立体框三维字段与跟踪 ID 保留；
- 项目工具：保存类别作业方式、导出下载；
- 200 万点加载与选区耗时。

测试页、合成数据与 Playwright 脚本**不提交到仓库**；合成场景生成方法见附录 A。

### 3.3 新格式 / 新导出的测试要求

- 每种新输入格式：至少一个真实样本 + 一个手工构造的边界样本（无效点、大坐标、最小文件）。
- 每种新导出写出器：一组“输入整包 → 期望文件”的固定样例，纳入后端单测。

## 4. 部署与配置

### 4.1 上线步骤

1. 执行 `labeling-server/docs/数据库/labeling_pointcloud_migrate.sql`（建 `lbl_pc_project_config`，幂等）。未执行时：作业台仍可按默认“只拉框”作业，但读取 / 保存类别作业方式会失败。
2. 部署后端与前端（与平台其它模块一同发布，无单独服务）。
3. 权限：沿用平台已有权限码，无需新增——质检 / 审核接口要求 `labeling:task:review` 或 `labeling:task:audit`；保存作业方式要求 `labeling:project:update`；导出要求 `labeling:dataset:export`。
4. 按 §4.2 调整参数，用 TC-01、TC-18 做上线冒烟。

### 4.2 参数

| 参数 | 位置 | 建议值 | 原因 |
|---|---|---|---|
| `OSS_MAX_FILE_SIZE` | 后端环境变量 | ≥ 200 MB | 默认 10 MB，单帧点云常见 2–50 MB |
| `OSS_MAX_ZIP_UPLOAD_SIZE` | 后端环境变量 | 默认 200 MB，可按批次调大 | zip 导入 |
| `spring.servlet.multipart.*` | `application.yml` | 与上面一致 | 仅影响经后端中转的上传 |
| 反向代理请求体上限（如 nginx `client_max_body_size`） | 网关 | ≥ 32 MB | 草稿 / 提交 JSON 含分割层，可达数 MB |
| 反向代理读超时（如 `proxy_read_timeout`） | 网关 | ≥ 300 s | 训练包为同步生成，大数据集需要时间 |
| MySQL `max_allowed_packet` | 数据库 | ≥ 64 MB | 写入大 JSON（后端整包上限 64 MB） |
| 对象存储 CORS | 存储桶 | 允许作业台域名 `GET`，暴露 `Content-Length` | 编辑器用 `fetch` 下载点云二进制 |
| 预览签名有效期 `OSS_SIGNED_URL_EXPIRE_SECONDS` | 后端环境变量 | 默认 1800 s 可用 | 点云打开时一次下载；加载失败时点“重新加载”，作业台会先刷新签名地址再重试 |
| 后端 JVM 堆 | 启动参数 | 导出期间按“帧数 × 4 B × 点数”估算峰值 | 训练包在内存中生成 |
| 客户端 | 作业电脑 | Chrome / Edge 稳定版、WebGL 2、内存 ≥ 16 GB、独立显卡优先 | 百万级点渲染与选区 |

## 7. 与伙伴模块的对接事项

以下事项涉及其它模块，点云侧**均未修改**对方代码。“影响”一栏说明不处理时点云作业台的表现。

| # | 事项 | 涉及模块 | 现状与影响 | 建议 | 优先级 |
|---|---|---|---|---|---|
| J1 | 点云明细直达独立页面 | 路由 / 作业台壳 | 目前经壳挂载 `LidarEditor` 后全屏覆盖；壳仍在底层加载一次任务上下文，功能无影响 | 可选：壳或路由对 `lidar` 明细直接渲染 `PointCloudWorkbench`（一处判断），省去一次加载 | 低 |
| J2 | 中台通用规范化改写立体框 | 中台标注校验 `OntologyAnnotationValidator` / `LblAnnotationJson` | 已复现：经通用提交接口时 `cuboid` 被改写为 `rect`、三维字段丢失；通用草稿与质检写回只保留整包模型内字段。点云已改走自有接口，不受影响 | 图像模块的立体框、椭圆、掩膜、折线等图形可能同样受影响（代码阅读所得，未逐一复现），请图像 / 中台负责人确认 | 中（影响其它模块） |
| J3 | 质检保存依赖 `saveReviewNotes` 的整包参数 | 中台 `TaskService` | `saveReviewNotes` 要求带整包并按通用模型写一次；点云在同一事务内随后以点云整包覆盖，结果正确 | 若对方修改该方法（如改为异步、或拒绝未知图形），请提前告知；或提供“仅校验质检权限”的方法 | 中 |
| J4 | 分割项目结算单位 | 中台结算 / 标注类型目录 | 点云统一用“立体框 / 点云”类型，按目标计价（计 `shapes` 个数）；纯分割项目需把费率的目标单价与基础价设为 0 才会按条计价 | 可选：新增“点云语义分割”类型并映射为按条计价 | 中 |
| J5 | 异步导出作业接入 | 数据集导出作业 | 点云训练包目前为同步下载，适合数千帧以内 | 大规模交付前，在导出作业中增加“点云训练包”格式，直接调用 `PointCloudExportWriter.write(classes, manifests)`（静态方法，无 Spring 依赖） | 中（二期前） |
| J6 | 导入接受 `.laz` | 公共常量（媒体扩展名） | 点云导入允许 `.laz`，但作业台不解析 LAZ，打开时提示“暂不支持 LAZ 压缩格式，请转换为 LAS 或 PCD 后导入” | 从点云可选扩展名中移除 `.laz`，或在导入页提示“LAZ 需先解压为 LAS” | 低 |
| J7 | 测试数据说明过时 | `labeling-server/docs/测试数据/README.md` 第 13 节 | 仍描述旧版编辑器（OrbitControls、PCDLoader、G/R/T 缩放） | 按 [08 §6](./08-一期交付说明.md#6-给伙伴的替换文本) 提供的替换文本更新 | 低 |
| J8 | 作业人员“可作业媒体”无点云 | 人员档案常量 | 仅档案字段，不影响派工 | 如需按媒体筛选人员，增加“点云” | 低 |

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 真实样本迟迟不到 | 协议与导出无法冻结 | W1 明确截止日；先用公开数据集（KITTI、SemanticKITTI）按同格式联调 |
| 伙伴修改依赖接口（§1.2） | 点云作业台加载或流转失败 | 依赖清单同步给伙伴；合入主干后必跑 §3；`PointCloudServiceImplTest` 固定了与中台的调用顺序 |
| 甲方坐标系与内部约定不同 | 框位置 / 朝向错 | 接入时确认并在预处理或导出写出器转换（02 §2） |
| 作业电脑性能不足 | 大点云卡顿 | W3 在目标硬件实测；必要时规定单帧上限或提前做二期性能项 |
| 无序点云分割层体积大 | 保存慢、数据库包超限 | 调大 §4 参数；体积超过 5 MB 的项目提前实施标签块外置 |
| 同步导出数据量大 | 网关超时、后端内存高 | 按数据集分批导出；大规模交付前完成 J5 |
| 跟踪项目跨帧 ID 一期靠人工 | ID 串号 | 序列整段派给同一人；质检重点检查；二期上自动检查 |
| 测试与业务人员与原项目验收冲突 | 排期顺延 | 点云测试窗口排在原项目验收之后（§8） |
| 选区穿透误改 | 错标 | 默认“仅改未标注”、高度裁剪、隐藏类别；撤销可回退 |
