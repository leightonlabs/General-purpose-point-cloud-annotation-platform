| 项 | 内容 |

## 1. 存储位置与原则

- 结果是一个 JSON 整包（`format: "lbl-v1"`），存于 `lbl_manifest.annotations_json`（MySQL `json` 列）。草稿与提交写同一字段，提交时经后端严格校验后回写规范化结果。
- 点云扩展**只增字段、不改已有字段含义**：根字段 `pointCloud`、`pointSeg`；`shapes[]` 中 `type: "cuboid"` 的立体框。
- 后端整包模型不逐字段建模点云内容；保存、提交、质检写回时通过“保留未建模字段”机制（`LblAnnotationJson.preserveUnmodeled`）原样保留。

## 3. `pointCloud`：结果与点云的绑定

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `pointCount` | int ≥ 0 | 是 | 文件总点数（含无效点） |
| `digest` | string | 是 | 点序摘要，算法见 [02 §3](./02-数据接入规范.md#3-点序与点身份强制) |
| `origin` | number[3] | 否 | 局部原点（仅说明用途，几何结果均为原始坐标） |
| `format` | string | 否 | `pcd` / `ply` / `bin` / `las` / `npy` |
| `fields` | string[] | 否 | 原始字段名 |

编辑器首次打开样本时写入；之后每次打开对比点数与摘要（见 §7）。

## 4. 立体框 `shapes[type=cuboid]`

| 字段 | 类型 | 必需 | 约束 |
|---|---|---|---|
| `key` | string | 是 | 本帧唯一，创建后不变；后端靠它保留三维字段，**不得缺省** |
| `type` | `"cuboid"` | 是 | |
| `classId` / `label` | string | 是 | 类别 ID 必须在冻结本体中，且类别几何包含 `cuboid`（或未声明几何）；`label` 提交时由后端按本体回写 |
| `center` | number[3] | 是 | **框几何中心**（不是底面中心），原始坐标，米 |
| `size` | number[3] | 是 | `[长, 宽, 高]`，长沿航向，均 > 0 |
| `yaw` | number | 是 | 度，绕 +Z 逆时针，0 指向 +X，前端写入 [0, 360) |
| `trackId` | string | 否 | 跨帧身份；本帧内唯一；≤ 64 字符；建议纯数字字符串 |
| `attributes` | `{attrId,name,value}[]` | 否 | 必填属性由规范决定，提交时校验 |
| `source` | `manual` / `prelabel` | 否 | 预标来源标记 |
| `occluded` / `truncated` | boolean | 否 | 沿用作业台通用标记 |

一期只有航向角（绕 Z），不含俯仰/横滚；地面坡度较大的场景需在规范里约定处理方式（二期评估 `pitch`/`roll`）。

## 5. 逐点分割层 `pointSeg`

| 字段 | 类型 | 必需 | 约束 |
|---|---|---|---|
| `encoding` | string | 是 | 一期仅 `rle-varint-v1`；读取方遇到未知编码必须拒绝，不得猜测 |
| `pointCount` | int | 是 | 等于 `pointCloud.pointCount`；≤ 8,000,000 |
| `digest` | string | 是 | 等于 `pointCloud.digest` |
| `palette` | `{index,classId,label}[]` | 是 | `index` 1–65535 且唯一；`0` 固定表示未标注，不出现在调色板中 |
| `data` | string | 是 | 编码后的 base64 |

### 5.1 `rle-varint-v1` 编码

1. 逐点标签数组 `L`，长度 = `pointCount`，`L[i]` 为第 i 个原始点的调色板索引（0 = 未标注），取值 0–65535。
2. 把 `L` 切成游程，按顺序写出每个游程的 `(值, 长度)`，两个数都用 LEB128 无符号变长整数编码（每字节低 7 位为数据，最高位 1 表示后面还有字节）。
3. 对字节流做标准 base64（含 `=` 填充）。空数组编码为空串。

示例：`L = [0,0,1,1,1,2,0]` → 游程 `(0,2)(1,3)(2,1)(0,1)` → 字节 `00 02 01 03 02 01 00 01` → `AAIBAwIBAAE=`。

解码要求：游程长度 > 0；累计长度必须恰好等于 `pointCount`；数据截断、超长或值 > 65535 一律报错。前端（TS）与后端（Java）的实现以同一组测试向量互相校验（`PointSegCodecTest`）。

### 5.2 体积参考

按扫描顺序存储的激光雷达点云，标签空间连续，游程少，通常远小于 1 字节/点；无序点云（例如随机重排后的地图点云）游程碎片化，最坏约 1 字节/点（实测 200 万无序点 ≈ 2 MB JSON）。二期把大标签块外置到对象存储（§8）。

### 5.3 调色板与规范版本

- 编辑器打开时按“当前冻结规范中允许 `point_seg` 的类别顺序”生成调色板，并按 `classId` 把已存标签重映射过去；**已存调色板里有、但当前规范没有的类别会被保留**并以“已不在规范中”标红，提交时作为硬错误要求改标，避免静默丢数据。
- 落库时写出完整调色板；后端只认 `classId`，不依赖索引顺序。

## 6. 预留扩展（二期，未实现）

| 扩展 | 预留形式 |
|---|---|
| 实例分割 | 新根字段 `pointInst`：同样的编码与绑定字段；`instances: [{index, classId, trackId?, shapeKey?}]` |
| 连续帧 | 根字段 `frame: {sequence, index, timestampUs}`；`trackId` 作用域 = 序列 |
| 三维折线 / 区域 | `shapes[type=polyline3d / polygon3d]`，`points3d: number[][3]` |
| 俯仰 / 横滚 | 立体框可选 `pitch` / `roll`（度） |
| 大标签块外置 | `pointSeg.dataRef: {storage, objectKey, sha256}` 替代 `data` |

新增字段一律为可选，旧数据无需迁移；新增编码用新的 `encoding` 名称。

## 7. 校验规则

| # | 规则 | 前端（提交前） | 后端（正式提交） |
|---|---|---|---|
| V1 | 立体框 center/size/yaw 为有限数值，size > 0 | 硬错误 | 拒绝 |
| V2 | 立体框类别在规范中且允许 `cuboid` | 硬错误 | 拒绝 |
| V3 | 本帧 `trackId` 不重复、≤ 64 字符 | 硬错误 | 拒绝 |
| V4 | 必填属性已填 | 硬错误（作业台通用） | 拒绝（通用） |
| V5 | 框内点数 < 1 | 提醒 | — |
| V6 | `pointSeg` 编码、点数、摘要与 `pointCloud` 一致，数据可解码 | 打开时检查，不一致禁止编辑并硬错误 | 拒绝 |
| V7 | 标签值都在调色板中；用到的类别在规范中且允许 `point_seg` | 硬错误 | 拒绝 |
| V8 | 仍有未标注点 | 提醒（显示数量与占比） | — |
| V9 | 点云未加载成功 | 硬错误 | — |

草稿保存不做 V1–V8 的严格校验（允许中间态），但同样保留全部点云字段。

## 8. 导出包 `pointcloud`

在“数据集 → 导出作业”中选择“点云 zip”。仅导出含立体框或逐点标签的帧；可叠加“仅已验收”“时间窗”“按任务筛选”等原有条件。

```text
<数据集>_pointcloud.zip
├── export_manifest.json        # 每个样本是否导出及原因（原有）
├── classes.names               # 每行一个导出名（原有）
├── classes.json                # [{id, classId, name, exportName}]：id 即语义 id
├── annotations/<stem>.json     # 逐帧结果（见下）
├── openpcdet/<stem>.txt        # 有立体框的帧
└── semantic/<stem>.label       # 有分割层的帧
```

| 文件 | 格式 |
|---|---|
| `classes.json` | 语义 id：类别 `categoryId`（> 0）优先，否则按启用类别顺序从 1 递增；0 保留为未标注 |
| `annotations/<stem>.json` | `{manifestCode, objectKey, pointCloud, objects:[{key, trackId, classId, className, exportName, center, size, yawDeg, yawRad, attributes}], segmentation:{file, pointCount, unlabeled, classes:[{semanticId, classId, points}]}}` |
| `openpcdet/<stem>.txt` | 每行 `x y z dx dy dz heading_angle category_name`（OpenPCDet 自定义数据集格式）；中心为框几何中心，`heading_angle` 为弧度，范围 [-π, π)；`category_name` 为导出名（exportCode → englishName → name，空格替换为下划线） |
| `semantic/<stem>.label` | SemanticKITTI 格式：每点一个 uint32 小端，低 16 位为语义 id，高 16 位实例 id（一期为 0）；长度 = 4 × `pointCount`，点序与原文件一致；调色板中已不在规范的类别写 0 |

注意：

- `<stem>` 为对象存储文件名去扩展名，数据集内必须唯一（[02 §4.3](./02-数据接入规范.md#43-命名规则)）。
- KITTI 3D（相机坐标、底面中心、需要标定）、nuScenes、甲方专有格式不在一期通用包内，按“导出适配器”单独开发，输入统一取本协议。
- 分割层损坏会导致导出作业失败并给出原因，不会输出部分错误数据。
