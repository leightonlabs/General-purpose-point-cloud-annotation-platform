## 1. 存储位置与原则

- 结果是一个 JSON 整包（`format: "lbl-v1"`、`media: "lidar"`），存于 `lbl_manifest.annotations_json`（MySQL `json` 列）。草稿与提交写同一字段。
- **点云样本的结果只经 `/api/labeling/pointcloud/**` 写入**。中台通用的保存 / 提交接口按图像模型规范化整包，会把立体框改写为矩形、丢弃分割层，因此点云作业台不调用它们；点云接口写入结果后，再调用中台 `TaskService` 完成状态流转（调用时不带整包），两步在同一事务内。
- 点云扩展**只增字段、不改已有字段含义**：根字段 `pointCloud`、`pointSeg`；`shapes[]` 中 `type: "cuboid"` 的立体框。
- 读写两端都是“宽进严出 + 原样保留”：前端解析时保留未知根字段与非立体框图形（`PcResult.extra` / `otherShapes`），立体框上的未知字段随框保留（`PcCuboid.extra`）；后端以 JSON 树处理，只补齐 `format` / `media`、提交时回写立体框 `label`，其余字段原样落库。

## 3. `pointCloud`：结果与点云的绑定

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `pointCount` | int ≥ 0 | 是 | 文件总点数（含无效点） |
| `digest` | string | 是 | 点序摘要，算法见 [02 §3](./02-数据接入规范.md#3-点序与点身份强制) |
| `origin` | number[3] | 否 | 局部原点（仅说明用途，几何结果均为原始坐标） |
| `format` | string | 否 | `pcd` / `ply` / `bin` / `las` / `npy` |
| `fields` | string[] | 否 | 原始字段名 |

编辑器首次加载点云成功时写入；之后每次打开对比点数与摘要（§7 V6）。存在 `pointCloud` 时，提交校验要求 `pointCount` 为非负整数且 `digest` 非空。

## 4. 立体框 `shapes[type=cuboid]`

| 字段 | 类型 | 必需 | 约束 |
|---|---|---|---|
| `key` | string | 是 | 本帧唯一，创建后不变；问题单 `shapeKey` 与导出 `key` 都靠它关联 |
| `type` | `"cuboid"` | 是 | |
| `classId` / `label` | string | 是 | 类别必须在任务冻结规范中、未停用，且该类别的作业方式包含“立体框”；`label` 提交时由后端按规范回写 |
| `center` | number[3] | 是 | **框几何中心**（不是底面中心），原始坐标，米 |
| `size` | number[3] | 是 | `[长, 宽, 高]`，长沿航向，均 > 0 |
| `yaw` | number | 是 | 度，绕 +Z 逆时针，0 指向 +X；前端写入 [0, 360)，保留 3 位小数 |
| `trackId` | string | 否 | 跨帧身份；本帧内唯一；≤ 64 字符；建议纯数字字符串 |
| `attributes` | `{attrId,name,value}[]` | 否 | 必填属性由规范决定，提交时校验（遵守一层 `visibleWhen` 条件） |
| `source` | `manual` / `prelabel` | 否 | 预标来源标记；人工改动后置为 `manual` |

一期只有航向角（绕 Z），不含俯仰 / 横滚；地面坡度较大的场景需在规范里约定处理方式（二期评估 `pitch` / `roll`）。

## 5. 逐点分割层 `pointSeg`

| 字段 | 类型 | 必需 | 约束 |
|---|---|---|---|
| `encoding` | string | 是 | 一期仅 `rle-varint-v1`；读取方遇到未知编码必须拒绝，不得猜测 |
| `pointCount` | int | 是 | 等于 `pointCloud.pointCount`；≤ 8,000,000 |
| `digest` | string | 是 | 等于 `pointCloud.digest` |
| `palette` | `{index,classId,label}[]` | 是 | `index` 1–65535 且唯一；`0` 固定表示未标注，不出现在调色板中 |
| `data` | string | 是 | 编码后的 base64 |

### 5.1 `rle-varint-v1` 编码

1. 逐点标签数组 `L`，长度 = `pointCount`，`L[i]` 为第 i 个原始点的调色板索引（0 = 未标注），取值 0–65535。
2. 把 `L` 切成游程，按顺序写出每个游程的 `(值, 长度)`，两个数都用 LEB128 无符号变长整数编码（每字节低 7 位为数据，最高位 1 表示后面还有字节）。
3. 对字节流做标准 base64（含 `=` 填充）。空数组编码为空串。

示例：`L = [0,0,1,1,1,2,0]` → 游程 `(0,2)(1,3)(2,1)(0,1)` → 字节 `00 02 01 03 02 01 00 01` → `AAIBAwIBAAE=`。

解码要求：游程长度 > 0；累计长度必须恰好等于 `pointCount`；数据截断、超长或值 > 65535 一律报错。前端（`pointLabels.ts`）与后端（`PointSegCodec.java`）用同一组测试向量互相校验：

| 向量 | 编码结果 |
|---|---|
| `[0,0,1,1,1,2,0]` | `AAIBAwIBAAE=` |
| 30 万点：1,000 个 0、249,000 个 3、49,999 个 0、1 个 65535 | `AOgHA6iZDwDPhgP//wMB` |

### 5.2 体积参考

按扫描顺序存储的激光雷达点云，标签空间连续，游程少，通常远小于 1 字节/点；无序点云（例如随机重排后的地图点云）游程碎片化，最坏约 1 字节/点（实测 200 万无序点 ≈ 2 MB JSON）。整包上限 64 MB（后端拒收更大的请求）；二期把大标签块外置到对象存储（§6）。

### 5.3 调色板与规范版本

- 编辑器打开时按“当前规范中作业方式含‘逐点分割’的类别顺序”生成调色板，并按 `classId` 把已存标签重映射过去；**已存调色板里有、但当前规范没有的类别会被保留**，在分割类别列表中标红“（已不在规范中）”，提交时作为硬错误要求改标，避免静默丢数据。
- 落库时写出完整调色板；后端与导出只认 `classId`，不依赖索引顺序。

## 6. 预留扩展（二期，未实现）

| 扩展 | 预留形式 |
|---|---|
| 实例分割 | 新根字段 `pointInst`：同样的编码与绑定字段；`instances: [{index, classId, trackId?, shapeKey?}]` |
| 连续帧 | 根字段 `frame: {sequence, index, timestampUs}`；`trackId` 作用域 = 序列 |
| 三维折线 / 区域 | `shapes[type=polyline3d / polygon3d]`，`points3d: number[][3]` |
| 俯仰 / 横滚 | 立体框可选 `pitch` / `roll`（度） |
| 大标签块外置 | `pointSeg.dataRef: {storage, objectKey, sha256}` 替代 `data` |

新增字段一律为可选，旧数据无需迁移；新增编码用新的 `encoding` 名称。

## 7. 校验规则

“作业方式”指项目点云配置中的类别作业方式（[04 §2](./04-项目规范配置.md#2-类别作业方式)），未配置的类别默认只拉立体框。

| # | 规则 | 前端（`lidarValidation.ts`，提交 / 通过前） | 后端（`PointCloudResultValidator.normalizeStrict`，提交 / 通过） |
|---|---|---|---|
| V1 | 立体框 center / size / yaw 为有限数值，size > 0 | 硬错误 | 拒绝 |
| V2 | 立体框 `key` 非空且本帧唯一 | 由前端生成保证 | 拒绝 |
| V3 | 立体框类别在冻结规范中、未停用，作业方式含“立体框” | 硬错误 | 拒绝 |
| V4 | 本帧 `trackId` 不重复、≤ 64 字符 | 硬错误 | 拒绝 |
| V5 | 必填属性已填（条件属性只在条件满足时必填，含子属性） | 硬错误 | 拒绝 |
| V6 | `pointSeg` 编码受支持；点数、摘要与 `pointCloud` 一致；数据可解码 | 打开时检查，不一致禁止分割编辑并作为硬错误 | 拒绝；有 `pointSeg` 而无 `pointCloud` 也拒绝 |
| V7 | 调色板索引 1–65535、唯一、`classId` 非空；标签值都在调色板中 | 打开时检查 | 拒绝 |
| V8 | 被逐点使用的类别在冻结规范中，且作业方式含“逐点分割” | 硬错误 | 拒绝 |
| V9 | 框内点数 < 1 | 提醒 | — |
| V10 | 仍有未标注点 | 提醒（显示数量与占比） | — |
| V11 | 点云未加载成功 | 硬错误 | — |
| V12 | 整包是 JSON 对象，≤ 64 MB | — | 拒绝（草稿同样检查） |

- 草稿保存、质检保存、驳回只做 V12（允许中间态），同样保留全部点云字段。
- 冻结规范为空（未钉定规范的旧任务）时，后端跳过 V3、V5、V8，其余规则照常。
- 后端规则以第一条失败为准返回中文原因，前端把原因原样提示给作业员。

## 8. 点云接口

前缀 `/api/labeling/pointcloud`。返回沿用平台 `Result` 包装；业务失败返回 `Result.error(中文原因)`。明细类接口要求作业账号登录，执行人 / 持有人、状态与权限校验由中台 `TaskService` 完成。

| 方法与路径 | 用途 | 请求体 | 权限 | 中台调用 |
|---|---|---|---|---|
| `POST items/{id}/draft` | 标注草稿 | `{annotationsJson}`（可空） | 作业账号 | `saveDraftItem`（`todo → doing`） |
| `POST items/{id}/submit` | 提交 | `{annotationsJson}` | 作业账号 | 严格校验 → 写整包 → `submitItem`（计量结算） |
| `POST items/{id}/review` | 质检 / 审核保存改动与问题单 | `{annotationsJson}` | 质检或审核 | `saveReviewNotes` 后以点云整包覆盖 |
| `POST items/{id}/accept` | 通过（可带改动） | `{annotationsJson}`（可空） | 质检或审核 | 有改动时严格校验并写入 → `acceptItem` |
| `POST items/{id}/reject` | 驳回 | `{annotationsJson, rejectReason, rejectReasonCode}` | 质检或审核 | 写整包 → `rejectItem` |
| `GET projects/{projectId}/config` | 读类别作业方式 | — | 项目可读 | — |
| `PUT projects/{projectId}/config` | 存类别作业方式 | `{classModes:[{classId, modes}]}` | 项目编辑 | — |
| `GET datasets/{datasetId}/export?onlyAccepted=true` | 下载点云训练包 | — | 数据集导出 | — |

读取结果沿用中台 `GET /api/labeling/task/items/{id}/workbench`（只读调用），从 `manifest.annotationsJson` 取整包。

## 9. 点云训练包

在点云作业台“项目工具 → 导出点云训练包”下载，导出当前样本所在的数据集；默认“仅已验收样本”（样本 `asset_status = accepted`），可取消勾选导出全部有结果的样本。同步生成 zip 返回，响应头 `X-Frame-Count` 为导出帧数。

```text
pointcloud_dataset_<数据集ID>.zip
├── classes.json                # [{id, classId, name, exportName}]：id 即语义 id
├── annotations/<stem>.json     # 逐帧结果（见下）
├── openpcdet/<stem>.txt        # 有立体框的帧
├── semantic/<stem>.label       # 有分割层的帧
└── export_report.json          # 每个样本是否导出及原因
```

| 文件 | 格式 |
|---|---|
| `classes.json` | 项目钉定规范中未停用的类别。语义 id：类别 `categoryId`（1–65535）优先，否则按类别顺序从 1 起取未被其它类别显式占用的编号；0 保留为未标注；`categoryId` 超过 65535 时导出失败。多个类别填同一 `categoryId` 视为有意合并为同一语义类 |
| `annotations/<stem>.json` | `{manifestCode, objectKey, pointCloud, objects:[{key, trackId, classId, className, exportName, center, size, yawDeg, yawRad, attributes}], segmentation:{file, pointCount, unlabeled, classes:[{semanticId, classId, points}]}}` |
| `openpcdet/<stem>.txt` | 每行 `x y z dx dy dz heading_angle category_name`（OpenPCDet 自定义数据集格式）；中心为框几何中心，`heading_angle` 为弧度，范围 [-π, π)；`category_name` 为导出名（exportCode → englishName → name，空白替换为下划线） |
| `semantic/<stem>.label` | SemanticKITTI 格式：每点一个 uint32 小端，低 16 位为语义 id，高 16 位实例 id（一期为 0）；长度 = 4 × `pointCount`，点序与原文件一致；调色板中已不在规范的类别写 0（计入 `unlabeled`） |
| `export_report.json` | `[{manifestId, manifestCode, included, file?, reason?}]`；`reason`：`no_result`（无结果）、`no_pointcloud_result`（没有可导出的立体框或分割层） |

注意：

- `<stem>` 为对象存储文件名去扩展名（没有对象键时用样本编码），数据集内必须唯一（[02 §4.3](./02-数据接入规范.md#43-命名规则)）；重名时整包导出失败并提示重名的文件。
- 类别不在当前规范中的立体框不写入导出（作业台提交校验已阻止这种结果，通常只出现在规范变更前的历史数据中）。
- 分割层编码不受支持或损坏时整包导出失败并给出样本与原因，不会输出部分错误数据；没有任何可导出帧时返回“没有可导出的点云结果”。
- 一期为同步导出，适合单数据集数千帧以内；更大规模接入中台的异步导出作业见 [07 §7](./07-研发规范与一期计划.md#7-与伙伴模块的对接事项)。
- KITTI 3D（相机坐标、底面中心、需要标定）、nuScenes、甲方专有格式不在一期通用包内，按“导出写出器”单独开发，输入统一取本协议。
