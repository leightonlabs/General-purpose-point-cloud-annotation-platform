# 点云数据接入规范

| 项 | 内容 |
|----|------|
| 文档编号 | PCD-SPEC-DATA-001 |
| 版本 | V1.0（一期） |
| 日期 | 2026-10-22 |
| 适用 | 数据接收、预处理、导入、项目经理 |
| 实现依据 | `labeling-admin-web/src/workbench/editors/lidar/pointCloudFormats.ts`（解析与摘要） |

本规范回答三件事：**什么数据能进平台、进来之前要检查什么、进来之后哪些东西不能再改**。标注结果与点云文件按“原始点序”绑定，接入环节的错误会直接变成标注错误，因此本规范中的“必须”均为准入条件。

---

## 1. 一期支持的文件格式

| 格式 | 编码 | 必需字段 | 读取的可选字段 | 说明 |
|---|---|---|---|---|
| PCD | `ascii` / `binary` / `binary_compressed`（LZF） | `x y z` | 强度：`intensity` / `i` / `reflectance` / `remission` / `scalar_intensity`；颜色：`rgb` / `rgba`（打包整数或打包 float） | `TYPE` 支持 F（4/8 字节）、I、U（1/2/4/8 字节）；`COUNT>1` 的字段可存在但不读取 |
| PLY | `ascii` / `binary_little_endian` / `binary_big_endian` | `vertex` 元素的 `x y z` | `red green blue`（uchar / ushort / 0–1 float）、强度同上 | 只读 `vertex`；二进制文件中 `vertex` 之前不得有含 list 属性的元素 |
| BIN | KITTI 布局 | 每点 float32 ×4：`x y z intensity`，小端 | — | 文件长度必须是 16 字节整数倍；**其它 BIN 布局一律在预处理中转换**，不得按后缀猜测 |
| LAS | 1.0–1.4，点格式 0–10，未压缩 | X/Y/Z（按头部 scale/offset 还原） | Intensity、RGB（16 位色自动缩到 8 位） | LAZ 拒收，需先解压为 LAS |
| NPY | v1–v3，`<f4` / `<f8`，形状 `(N, C)`，C ≥ 3 | 列 0–2 为 `x y z` | 列 3 视为强度 | C 序与 Fortran 序均可 |

不在上表的格式（E57、自定义二进制、ROS bag、点云 + 图像融合包等）在接入环节转换为上表格式后再导入；转换脚本、参数与版本须随数据说明一起归档。

## 2. 坐标、单位与角度约定（内部统一约定）

| 项 | 约定 |
|---|---|
| 坐标系 | 右手系，**Z 轴向上**；编辑器直接使用文件中的坐标，不做任何变换 |
| 单位 | 米 |
| 立体框航向角 | 绕 +Z 轴逆时针为正，0° 指向 +X；落库为“度”，范围 [0, 360)；导出时按目标格式换算 |
| 地面 | 平台按 z 直方图在中位数以下的众数估计地面高度，作为新建框的落地高度；作业员可在工具栏修改 |
| 大坐标 | 任一坐标绝对值 > 1e4 时自动平移“局部原点”（PCD/PLY/BIN/NPY 取首个有效点取整，LAS 取头部最小值向下取整）；**结果仍按原始坐标保存**，`pointCloud.origin` 记录原点 |

接入时必须确认并在《数据说明》中写明：

1. 数据所在坐标系（传感器 / 车体 / 世界 / 地图），以及与交付坐标系的关系；
2. 若来源坐标系不是 Z 向上（例如相机坐标 Y 向下），**在预处理中转换为 Z 向上**并记录变换矩阵；
3. 单位（若为厘米/毫米须在预处理中换算为米）；
4. 是否已做运动补偿、是否已去除自车点、是否已做俯仰/横滚校正（影响“地面水平”的假设）。

> 上述约定是一期默认值。若甲方交付坐标与内部约定不同，在**导出适配器**里转换，不改内部约定。

## 3. 点序与点身份（强制）

| 规则 | 说明 |
|---|---|
| 点身份 = 原始点序 | 文件中第 i 个点（从 0 起）的标签存放在 `pointSeg` 标签数组第 i 位 |
| 无效点保留占位 | NaN / Inf 坐标的点不显示、不参与选区，但占用下标；有序点云（`HEIGHT>1`）中的空洞同样占位 |
| 不过滤、不降采样、不重排 | 导入后平台不改点序；预处理若需要去噪/裁剪，必须在**导入前**完成并形成新文件 |
| 点序摘要 digest | `fnv1a32x2:<16 位十六进制>`：两路 FNV-1a 32 位哈希，输入为 `"<点数>|<ox>,<oy>,<oz>|"` 加全部局部坐标的 float32 小端字节 |
| 摘要与格式无关 | 同一组坐标与点序，PCD 与 BIN 得到相同摘要（已验证），因此“仅转换格式、不改点序与数值”不影响已有标签 |
| 摘要不一致 = 数据被换 | 打开任务时若已保存的逐点标签与当前文件的点数或摘要不一致，编辑器**禁止分割编辑与提交**，只能由管理员核对数据版本后处理 |

摘要仅用于发现“文件被替换、重排、裁剪”，不是安全校验。

## 4. 数据组织与命名

### 4.1 一帧一样本

- 一个点云文件 = 一个 Manifest = 一帧 = 一条作业明细。
- 一期不支持“一个文件含多帧”；连续帧以多个文件提供（序列作业见二期）。

### 4.2 交付目录（接收标准）

```text
<批次号>/
├── 数据说明.md              # 必需：来源设备、坐标系、单位、字段、预处理记录、帧数
├── manifest.csv             # 建议：file,sequence,frame,timestamp_us,remark
├── pointcloud/
│   ├── seq001_000000.pcd
│   ├── seq001_000001.pcd
│   └── ...
├── expected/                # 必需（首批）：甲方给出的期望交付样例，用于对齐导出格式
├── images/                  # 二期：相机图像（若有）
├── calib/                   # 二期：内外参
└── poses/                   # 二期：位姿
```

### 4.3 命名规则

| 规则 | 原因 |
|---|---|
| 文件名在**整个数据集内唯一**（不含扩展名） | 导出包以文件名作为 `annotations/`、`openpcdet/`、`semantic/` 下的文件名 |
| 推荐 `<序列>_<6 位帧号>.<ext>`，只用字母、数字、下划线、短横线 | 便于排序与跨系统传输 |
| 不在文件名中放中文、空格 | 避免对象存储与压缩包编码问题 |

### 4.4 导入方式（沿用中台）

| 方式 | 适用 |
|---|---|
| 数据集导入“选文件上传” | 少量小文件；受 `OSS_MAX_FILE_SIZE` 限制（默认 10 MB，点云项目需调大，见 07 §3） |
| zip 上传自动解压登记 | 一批中小文件（扩展名 `.pcd .ply .las .bin .npy`） |
| OSS 键清单 | 大文件或大批量：先用对象存储工具上传，再粘贴 object key 清单 |

## 5. 规模边界（一期）

| 单帧点数 | 平台行为 |
|---|---|
| ≤ 200 万 | 性能保证范围（需在目标硬件上复测，见 07 §5） |
| 200 万 – 800 万 | 可加载，顶部提示“点数较多，选区与重绘可能变慢” |
| > 800 万 | 拒绝加载，提示分块后导入；后端也拒绝 > 800 万点的分割层 |

参考内存：每点约 12 B 坐标 + 4 B 着色 + 2 B 标签 + 8 B 选区投影缓存（仅分割操作时），另有 GPU 显存。200 万点约 50 MB 内存。

参考实测（开发环境，无头浏览器 + 软件 WebGL，仅作量级参考）：19 万点场景加载与交互流畅；200 万点 BIN 本地加载约 1.3 s，一次套索赋类（投影 + 赋值 + 编码 + 重新着色）约 1.5 s。

## 6. 接收检查清单

每个批次接收时由数据接入负责人逐项检查并留档，**首批必须 100% 文件抽检解析**，之后每批至少抽检 5% 且不少于 20 个文件。

| # | 检查项 | 方法 | 通过标准 |
|---|---|---|---|
| D1 | 文件可解析 | 在作业台打开（或用同版本解析器脚本） | 无报错；格式与《数据说明》一致 |
| D2 | 点数 | 状态栏“有效/总点数” | 与说明一致；无效点比例超过 20% 需说明原因 |
| D3 | 坐标系朝向 | 俯视看地面是否为水平平面；透视看建筑/杆是否竖直 | Z 向上，地面基本水平 |
| D4 | 单位 | 量一辆车（贴合后看长宽高） | 小汽车约 4–5 m × 1.7–2 m × 1.4–1.8 m |
| D5 | 坐标范围 | 状态与“显示 z”初值 | 无异常离群（如 z 相差上千米） |
| D6 | 强度 / 颜色 | 切换“按强度”“RGB”着色 | 字段存在时可正常显示；值域写入说明 |
| D7 | 文件名唯一 | 清单去重 | 无重复 stem |
| D8 | 期望交付样例 | 对照 `expected/` | 能映射到导出包或已立项导出适配器 |
| D9 | 版本与归档 | 记录批次号、文件数、总大小、校验和 | 留档完整 |

## 7. 拒收或退回条件

- 解析失败、BIN 布局不明、LAZ 未解压、超过 800 万点未分块；
- 坐标系或单位无法确认；
- 文件名重复或含非法字符；
- 首批没有期望交付样例且甲方无法提供交付格式说明；
- 预处理在导入后才执行（会破坏点序）。

## 8. 数据版本规则

1. 文件一旦进入任务，**不得原位替换**（对象存储同 key 覆盖视为违规）。需要修正数据时，以新文件新建样本，旧样本按原平台规则处理（未进任务可删）。
2. 预处理脚本、参数、输入批次号随数据说明归档；同一批数据重复预处理必须得到相同点序与数值。
3. 若发现已标注数据被替换（编辑器出现“点云文件与已保存的逐点标签不一致”），停止作业，由管理员确认：恢复原文件，或作废该样本结果后重新标注。
