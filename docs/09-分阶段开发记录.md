## 1. 最终目标、约束与阶段划分

### 1.1 最终目标

一个统一的点云标注平台：公共点云底座 + 可复用的作业能力模块 + 按项目配置的规范 + 数据格式适配器，覆盖下列能力域，而不是为每个甲方单独开发一套平台。

| 能力域 | 最终要具备的能力 |
|---|---|
| 数据接入 | 常见格式与自定义 BIN 布局；单帧、连续帧、多站、融合地图；附带图像、标定、位姿、时间戳 |
| 显示与浏览 | 多种着色、裁剪、多视图、相机图像联动、大场景分块与 LOD |
| 目标与轨迹 | 立体框、跨帧轨迹（传播、插值、关联修正）、俯仰 / 横滚 |
| 点级标注 | 语义分割、实例分割、全景分割、时序实例 |
| 道路与地图要素 | 三维折线 / 区域、车道拓扑与关系 |
| 其它任务族 | 关键点与骨架、刚体位姿、占用体素、帧级分类与事件 |
| 规范与流程 | 类别、属性、作业方式、工具与质检规则配置；保存恢复、冲突处理、质检、返工、验收统计 |
| 交付 | 通用训练包 + 各甲方格式适配器；大规模异步导出 |
| 智能辅助 | 预标导入、模型预标、2D 掩码辅助 3D 分割、质检规则自动检查 |

### 1.2 开发约束

1. 代码只落在点云模块的路径内：前端 `labeling-admin-web/src/workbench/editors/lidar/`、`labeling-admin-web/tests/pointcloud/`；后端 `com.pmsm.zs.labeling.pointcloud` 包、`resources/mapper/pointcloud/`、对应测试目录、`labeling_pointcloud_migrate.sql`（[07 §1.1](./07-研发规范与一期计划.md#11-允许修改的路径)）。
2. 平台已有能力（任务、派工、权限、规范库、结算、对象存储）**只调用不修改**；依赖清单见 [07 §1.2](./07-研发规范与一期计划.md#12-对外依赖清单只调用不修改)。
3. 其它模块中尚未完整实现或仅为占位的组件不复用，点云需要的能力在点云模块内自建。
4. 需要其它模块配合的事项列入对接清单（[07 §7](./07-研发规范与一期计划.md#7-与伙伴模块的对接事项)），由对应负责人决定。
5. 后续各阶段的设计均以“不改其它模块也能交付”为前提；需要伙伴配合的部分只作为可选优化。

### 1.3 阶段划分

## 6. 推荐方案要点

1. **先把代码状态理顺**：开发分支合入 `main`（D1），同时把旧版共享改动中对其它模块有价值的修复以“问题 + 复现方式”交给对应负责人（D2），点云侧不再改动它们。
2. **继续坚持“点云自成模块”**：二期的序列索引（D4）、导出任务（D6 方案 B）、冲突检测（D12）、整帧属性配置都放在点云模块自己的表与接口中，伙伴配合只作为可选优化。
3. **协议先行、只增不改**：实例分割用独立 `pointInst` 层（D7），大标签块用 `dataRef` 外置（D11），连续帧用 `frame` 根字段，旧数据无需迁移（[03 §6](./03-标注结果协议.md#6-预留扩展二期未实现)）。
4. **以真实样本驱动排期**：一期收尾的关键路径是样本与联调环境（Q-A1、O1）；二期的范围按 Q-A4、Q-A7、Q-A8 的答复确定。
5. **效率以数据衡量**：试标记录单帧工时与驳回原因分布，作为二期“复制 / 插值 / 预标”是否有效的对比基线。
