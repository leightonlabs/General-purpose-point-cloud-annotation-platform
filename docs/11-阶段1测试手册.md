## 1. 测试环境准备

| # | 步骤 | 说明 |
|---|---|---|
| E1 | 部署后端与前端 | 与平台其它模块一同部署 |
| E2 | 执行迁移脚本 | `labeling-server/docs/数据库/labeling_pointcloud_migrate.sql`（新建 `lbl_pc_project_config`、`lbl_pc_frame_result`，幂等） |
| E3 | 对象存储 | 平台已支持的 OSS 或 S3 兼容存储（如 MinIO）；在平台“存储连接”中配置并绑定到测试项目 |
| E4 | 跨域 | 存储桶允许作业台域名 `GET`，暴露 `Content-Length`（作业台直接下载点云与图片） |
| E5 | 参数 | 代理请求体上限 ≥ 32 MB；MySQL `max_allowed_packet` ≥ 64 MB（见 [07 §4](./07-研发规范与一期计划.md#4-部署与配置)） |
| E6 | 账号 | 项目管理员（含项目编辑、数据集导出权限）、标注员、质检员、审核员各一个，标注员与质检员为作业账号 |
| E7 | 浏览器 | Chrome / Edge 最新版，开启硬件加速 |

## 2. 准备测试数据

```bash
python3 tools/testdata/gen_packages.py --out ./out --packages 2 --frames 20 --prefix labeling/pc-test
```

1. 把 `out/PCTEST_0001`、`out/PCTEST_0002` 两个目录按原结构上传到对象存储的 `labeling/pc-test/` 下（可用存储自带的上传工具）。
2. 记下 `out/import.csv` 与 `out/classes.json`。

## 3. 配置项目

| # | 步骤 | 期望 |
|---|---|---|
| P1 | 规范库新建点云规范（媒体类型：点云），按 `classes.json` 建 8 个类别：名称、颜色、英文名、基准编号（categoryId）照填；几何保持默认 | 发布成功 |
| P2 | 给“乘用车”加本类属性“遮挡”：单选（无 / 部分 / 严重），必填 | — |
| P3 | 加两个共用属性，作用范围选“整图”：“天气”（单选：晴天 / 雨天 / 雾天，必填）、“时间”（单选：白天 / 夜晚） | 作业台“场景属性”面板中出现这两项 |
| P4 | 建项目：媒体“点云”，标注类型“立体框 / 点云”，钉定上面的规范；开启质检 | — |
| P5 | 建数据集，导入方式选“OSS 键清单”，上传 `import.csv` | 数据集中出现 2 个样本（每包一个），编码为包编号 |
| P6 | 建标注任务并派给标注员 | 标注员待办中出现 2 条 |
| P7 | 管理员从任务详情以只读方式打开任一明细 → 顶栏“项目工具”：“乘用车”勾选立方体和刷点，其余类别只勾刷点；结算计量选“按已标注帧”；保存 | 提示保存成功 |

> 不要用平台的 zip 导入点云包：zip 导入会把每帧拆成一个样本，并丢弃图片与标定。

## 4. 测试用例

用例编号 S1-xx。“期望”中的数值以生成器默认参数（20 帧，单帧约 3.2 万点）为准。

### 4.1 打开与显示

| 编号 | 操作 | 期望 |
|---|---|---|
| S1-01 | 标注员从待办打开第 1 包 | 全屏点云作业台；顶栏显示任务名、包编号、“第 1/20 帧（时间戳）”；默认**合并帧**；渲染点数约 67 万 / 200 万；底部帧条 20 格 |
| S1-02 | 切换平台皮肤（经典蓝、科技青等）后重新打开 | 顶栏、侧栏、按钮主色随皮肤变化；三维画布保持深色 |
| S1-03 | 顶栏“单帧”，再点帧条第 5 格；按 `.` / `,` | 只显示该帧；前后切帧，帧条当前格高亮 |
| S1-04 | 右侧工具栏：顶、透、适；点、亮、高（勾选后拖动范围）、强、网 | 视角与显示按说明变化；高度过滤后选区只作用于显示的点 |
| S1-05 | 渲染点数卡片 → 上限改为 30 万 | 显示降采样；刷点仍作用于全部原始点（统计数变化与上限无关） |
| S1-06 | 右侧“相”（或 `C`） | 显示本帧前视、后视两张图片，点击放大 |

### 4.2 刷点（4D 分割，合并帧）

| 编号 | 操作 | 期望 |
|---|---|---|
| S1-10 | `T` 顶视角，`Q` 圈选，圈住路面区域 | 弹出“选择标注类型”，输入“地面”回车；左栏“地面”点数增加、未标注减少；帧条各格变为已标注 |
| S1-11 | 锁定“地面”（🔒），`B` 框选大范围，选“人行道” | 已是地面的点不变，其余点变为人行道 |
| S1-12 | `Ctrl+Z`、`Ctrl+Y` | 恢复 / 重做上一步，点数随之变化 |
| S1-13 | `-`（移除区域）后框选一块 | 该范围点恢复为未标注（锁定类别的点不变） |
| S1-14 | `E` 自由绘制，按住涂抹；`[` `]` 调半径 | 涂抹处实时变色；一笔为一次撤销 |
| S1-15 | `L` 折线选：单击加点，双击结束 | 沿折线一定宽度内的点被选中并弹出类别选择 |
| S1-16 | `W` 只改未标注后再框选 | 已标注的点不变 |
| S1-17 | 左栏眼睛隐藏某类 | 该类的点不显示，也不会被选中 |
| S1-18 | 顶栏“点数统计” | 各类点数、未标注、总点数与左栏一致 |

### 4.3 立方体（单帧）

| 编号 | 操作 | 期望 |
|---|---|---|
| S1-20 | 单帧，`Alt+1` 切到立方体，`T` 顶视角，`N` 后在车辆处拖出底面 | 生成立方体，高度按点估计；右栏对象列表出现，显示红色“!”（遮挡未填） |
| S1-21 | 拖动框体 | 框在地面上平移 |
| S1-22 | 拖动框底橙色旋转手柄 | 朝向随鼠标直接旋转，右栏航向变化 |
| S1-23 | 双击框（或 `Enter`） | 进入编辑模式：下方出现**正视、左视、俯视**三个视图，只显示框附近的点 |
| S1-24 | 在正视 / 左视 / 俯视中分别拖边、拖框、俯视图拖圆点 | 对应尺寸、位置、朝向变化，对边不动；三维中框同步 |

| 编号 | 操作 | 期望 |

### 4.5 保存、提交、质检

| 编号 | 操作 | 期望 |
|---|---|---|
| S1-40 | 修改后停手 3 秒 | 顶栏“已保存 时间”；帧条未保存标记消失 |
| S1-41 | 同一明细在两个窗口各改一次 | 后保存的窗口提示“已在其它窗口修改，请刷新后重试” |
| S1-42 | 断网修改后刷新页面 | 提示恢复本机暂存；恢复后联网自动保存 |
| S1-43 | 遮挡或天气未填时 `Ctrl+Enter` | 校验未通过，列出“第 n 帧：…缺少必填属性”“场景属性未填写” |
| S1-44 | 补齐后提交 | 有未标注点时提醒占比，确认后提交并回到待办列表；作业台内没有“下一包” |
| S1-45 | 质检员打开该明细 | 阶段显示“质检”；右栏“质检”中可对选中框或本帧提问题，帧条该帧出现红点 |
| S1-46 | 质检驳回 | 驳回理由自动汇总“问题类型（第 n 帧·第 k 个框）：说明” |
| S1-47 | 标注员返工 | 顶栏显示返工原因；点击问题跳到对应帧与框；可标记已解决后再次提交 |
| S1-48 | 质检通过 | 明细流转；结算计量值 = 已标注的有效帧数 |

### 4.6 导出与核对

| 编号 | 操作 | 期望 |
|---|---|---|
| S1-50 | 管理员打开明细 → 项目工具 → 导出点云训练包（先取消“仅已验收”） | 下载 zip |
| S1-51 | 检查 zip | 每个有效帧一组文件，文件名为 `<包编号>_<帧ID>`；`semantic/*.label` 字节数 = 4 × 该帧点数；`export_report.json` 中无效帧不出现 |
| S1-52 | 用测试包真值核对（可选） | `truth/<帧ID>.label` 为每点真值类别编号，与导出的语义 id（基准编号）可逐点对比，计算标注准确率 |

## 5. 自动化冒烟（研发自测）

不依赖数据库与对象存储，用模拟接口在浏览器中跑主路径：

```bash
cd annotation-platform/labeling-admin-web && npx vite --port 5199
python3 tools/testdata/gen_packages.py --out /tmp/pc-pkgs --packages 1 --frames 20
PWG=<playwright 所在 node_modules> node tools/e2e/workbench-smoke.mjs /tmp/shots /tmp/pc-pkgs/PCTEST_0001 tech-cyan
```

最近一次结果（10-23）：合并帧 20 帧约 67 万点加载约 2 s；圈选、锁定、框选、撤销重做、移除区域、自动保存、新建立方体、旋转手柄（航向 270° → 237°）、编辑模式三视图、相机图片、快捷键窗口、提交校验与提交全部通过；作业台壳的保存 / 提交接口调用 0 次；无页面错误。经典蓝、科技青皮肤下主色正确。
